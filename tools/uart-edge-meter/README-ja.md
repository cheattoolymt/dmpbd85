# Uno R3でBD85のF端子を測定

対象：ATmega328P搭載の16MHz Arduino Uno R3。
受信専用の簡易測定であり、UARTデコードや完全なロジックアナライザではない。
Timer1の入力キャプチャで立ち下がり時刻を192個まで記録する。
時刻の刻みは0.5µs。高密度のエッジでは割り込み処理が追いつかず欠落する可能性がある。
測定結果から高速通信の不存在やフレーミングの正常性は証明できない。

## 配線

BD85の電源を切り、UnoのUSBも外して組み替える。

1. **以前のUno RESET–GNDジャンパーを外す。** 今回は328Pでスケッチを実行する。
2. **BD85 F–Uno D1の配線を外す。** D0/D1とBD85をつなぐ配線は残さない。
3. BD85の確認済みGND（D）をUno GNDにつなぐ。
4. BD85 FをUno **D8**につなぐ。手元に1kΩ程度の抵抗があれば直列に入れてもよい。
5. BD85とUnoの3.3V/5V/Vinは接続しない。BD85は元のACアダプターで給電する。

| BD85 | Uno R3 |
| --- | --- |
| D（確認済みGND） | GND |
| F（約3.3Vの信号候補） | D8 / ICP1 |

UnoはUSB給電。D8はプルアップなしの入力であり、BD85にデータを送らない。

## アップロードと測定

1. Arduino IDEで `bd85_edge_meter/bd85_edge_meter.ino` を開く。
2. ボードにArduino Unoと該当COMポートを選び、書き込む。
3. シリアルモニターを **115200** で開く。これはPC–Uno間の速度で、F端子の速度指定ではない。
4. BD85が待機している状態で `g` を送信する。
5. `ARMED` が表示されたら、20秒以内にBD85を起動する。
6. 192エッジまたは20秒で終了し、`DONE` とCSVが表示される。
7. `DONE` から末尾までを保存する。`g` を再送すれば再測定できる。

完全な電源投入を測る場合は、BD85だけACアダプターを外しておき、
`ARMED` 表示後に接続する。起動方法を記録して、通常の待機→起動と区別する。
Unoのシリアルモニターを閉じてTera Termを使ってもよいが、同時には開かない。

## 結果の読み方

`delta_us` は**立ち下がりから次の立ち下がりまでの時間**で、1ビット幅そのものではない。
通常の非反転UARTなら、連続する立ち下がりの最短間隔は原則2ビット分。
複数の間隔が、下記のビット幅の整数倍に近いかを調べる。

| 候補速度 | 1ビット | 2ビット |
| --- | ---: | ---: |
| 9600 | 104.17µs | 208.33µs |
| 38400 | 26.04µs | 52.08µs |
| 57600 | 17.36µs | 34.72µs |
| 115200 | 8.68µs | 17.36µs |
| 230400 | 4.34µs | 8.68µs |

整数倍だけでは速度を一意に決定できない場合がある。
例えば17.5µs付近の間隔は115200の2ビットにも230400の4ビットにも近い。
単一の最短値だけで確定せず、間隔分布と既存の受信ログを合わせて判断する。
192エッジに達すると記録を止めるため、起動全体の速度変更はこの1回では分からない。

`DONE,edges=0` なら、測定窓内で立ち下がりを捕捉できていない。
配線・起動タイミングを確認する。UARTの不存在とは断定しない。

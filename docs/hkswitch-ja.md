# 起動ログの `HKswitch=1` と更新ファイルの照合

調査日：2026-11-11。対象は日本版DMP-BD85の公式更新ファイル1.81。

## 結果

実機から提供された115200設定のバイナリログには、オフセット `0x270` に
`\r\nHKswitch=1 \r\n` が存在する。一方、下記の範囲で更新ファイル内の
対応する文字列を発見できず、出力元関数・意味・前後の速度変更処理は未特定。
`HK` の略語や `1` の意味を推定で断定しない。

検索した通常ファイルは1,872個（うちrootfs内1,843個）、延べ325,917,674バイト。
抽出領域と元ファイル等の重複を含む。

検索対象：

- `PANA_DVD.FRM` 全体。
- BITから抽出したboot、FE、kernel、initrdなどの領域。
- 展開したLinuxカーネル。
- 通常SquashFSを展開したrootfs内の通常ファイル。シンボリックリンクは追跡しない。

`HKswitch` 単独に加え、`HKswitch=1`、`HKswitch=%d`、`%u`、`%x` を
ASCII・UTF-16LE・UTF-16BE、大文字小文字を区別せず検索したが一致なし。
したがって、数値が実行時に書式展開されるだけ、という説明では未発見を解消できない。
rootfsの印字可能文字列では `HK` と `switch` が近接する表記も調べたが、
該当する出力書式は見つからなかった。

BIT抽出領域にはさらに2/4バイトごとの各レーン、2/4バイト単位の逆順、
単一バイトXORを試したが、`HKswitch` の一致なし。
これは独自圧縮・暗号・動的文字列生成などを網羅した検証ではない。

## 未展開領域の追加確認

以下の4領域を対象にgzip・XZ・bzip2・SquashFS・newc cpio・LZ4 frameの
開始シグネチャを検索したが、一致なし。

| 抽出ファイル | zlib候補ヘッダー数 | 終端まで展開でき、出力が32バイトを超えたストリーム |
| --- | ---: | ---: |
| `01-boot_1-00000200.bin` | 4 | 0 |
| `19-kernel_2-00300000.bin` | 497 | 0 |
| `20-initrd_1-00000000.bin` | 156 | 0 |
| `22-rootfs_enc_it_1-00000000.bin` | 9 | 0 |

zlib候補は `78 01` / `78 5e` / `78 9c` / `78 da` を走査し、各候補から
最大16MiBまで展開して終端を検査した。raw DEFLATEや独自形式を排除した結果ではない。
高エントロピーや展開失敗だけで暗号化と断定しない。

## 速度について確認できた証拠

ブートローダーの環境領域（FRMオフセット `0x7c405`）には `baudrate=115200` が存在する。
実カーネルの `_mt85xx_uart_console_setup`（VA `0xc042647c`）も、
冒頭で115200（`0x1c200`）、8ビット、パリティなしを初期値に設定する。
ただし、その後にオプション解析等の分岐があり、この初期値だけで実行時の速度を保証しない。
また、このconsoleが基板F端子につながる証拠もまだない。

ログで一部が読めることから、全体を単一速度のテキストと決めつけたり、
起動途中の速度変更が存在すると断定したりはできない。

## 残る調査

1. 実機に導入済みのバージョンと更新ファイル1.81が一致するか確認する。
2. 未展開のpreloader・initrd等の読み込み処理を追い、形式を解明する。
3. 更新ファイルに含まれないコードや、実行時の文字列生成も候補として残す。

現段階では `HKswitch=1` をLinux自身のログと特定できていない。
実機の生ログと写真は、このリポジトリーには追加しない。
